# 06 · Quality Gate

## 何时使用
初稿完成、交稿前需要拦成稿 / 焦点 / 证据 / 读者 / 语言问题时使用。

## 目标
把交稿前最容易出事的五类问题，在交付前拦住。

## 输出
使用 `templates/quality-gate-result.md`

## 五道门

### Gate 0：成稿门
检查：
- 标题像不像成稿，而不是工作标题
- 小标题和段首句能不能支撑快速扫读
- 这篇稿像文章，还是像整理件 / 说明件 / 问答件
- 最强卖点有没有被前置，而不是埋到中后段

### Gate 1：焦点门
检查：
- 原素材主推对象是否始终稳居主轴
- 前 40% 正文里，主推对象是否已经清楚出现
- 外部补料有没有抢戏
- 品牌是否出现得太早、太硬、太满

### Gate 2：证据门
检查：
- 哪些句子是事实、口径、补强或判断
- 有没有把判断写成事实
- 有没有把公司口径写得过满
- 主推轴和证据轴有没有被偷换

### Gate 3：读者门
检查：
- 如果遮住品牌名，这篇稿还成立吗
- 如果删掉补料，主推对象还清不清楚
- 主读者为什么会继续读下去
- 这篇稿有没有沦为”把客户回复按顺序摆放好”的整理件
- 读者在第二段就能猜到结尾说什么吗——如果能，这篇稿缺少推进感
- 有没有段落在重复前面已经说过的判断，只是换了措辞

### Gate 4：语言门
检查：
- 有没有明显模板腔、解释腔、翻译腔
- 有没有句子过满、过匀、过度总结
- 有没有为了显得会写而硬加姿势词

## 回退规则
- 成稿门不过：回 `04-packaging.md`
- 焦点门不过：回 `03-structuring.md`
- 证据门不过：回 `02-evidence-layering.md`
- 读者门不过：回 `01-framing.md`
- 语言门不过：转 `07-de-ai.md`

## 工作步骤
0. 先不带清单通读一遍全文。记下第一反应：哪里卡、哪里无聊、哪里想跳过。这些直觉比任何门都准
1. 先按门检查，不先改字眼
2. 先判断该回哪一阶段
3. 只有五道门都过线后，才交稿

## 常见反模式
- 只检查语言，不检查焦点和证据
- 明明是结构问题，却一直抠句子
- 发现问题后，不指出该回哪一阶段修

## 停止条件
满足任一即可：
- 五道门全部 Pass，可以交稿
- 已产出明确回修清单，并指出要回哪一阶段
- 语言门单独不过，已明确转入 de-ai

## 一句话记忆
> 先过门，再交稿；语言只是最后一关，不是遮羞布。
